In one sentence

Clean your team’s messy air-quality export, build a leak-free virtual PM2.5 sensor and prove with numbers that the cleaning helps. You hand in one completed notebook: L1_Air_Quality_Data_Preprocessing_Notebook_<TeamName>.ipynb.

⏱ Week 1 · team assignment · 100 + 10 bonus points

Goal

The city’s environmental agency merged the exports of its 12 monitoring stations (Beijing Multi-Site Air Quality, UCI dataset 501) and introduced errors on top of the real gaps. Find and fix them, then estimate PM2.5 from gases, weather, time and station — without PM10 — and measure the improvement on the untouched final test year.

⏱ Day 1 · three steps

Getting Started

  1. Rename the notebook to L1_Air_Quality_Data_Preprocessing_Notebook_<TeamName>.ipynb (letters, digits and hyphens only, e.g. L1_Air_Quality_Data_Preprocessing_Notebook_DataFalcons.ipynb).
  2. In the setup cell, set TEAM_ID (your team number) and TEAM_NAME (same spelling as the file name).
  3. Run Part A, then work through Part B.

⏱ Part B · details are in the notebook

Tasks & Points

#TaskPoints

⏱ before Lecture 2 · nothing else to hand in

Deliverable — One Completed Notebook

File: L1_Air_Quality_Data_Preprocessing_Notebook_<TeamName>.ipynb, fully executed, containing:

  1. All code cells run, with outputs visible.
  2. Every “✍ Answer & conclusion” cell completed — answer its questions with numbers from the output and add a short conclusion.
  3. The Final summary cell (markdown, towards the end of the notebook) describing:
    • Findings — the issue log in brief;
    • Key decisions — imputation per gap length, outlier policy, transforms, dropped rows and possible bias;
    • Impact — naive vs cleaned metrics (RMSE, MAE, R²) and one plot;
    • Lessons for the agency;
    • (Bonus) HPC timings.

Before uploading, run Kernel → Restart & Run All, save, and run the Submission check cell: it must print “✓ ready to submit”. Upload to the submission space announced by the organisers, before Lecture 2. The notebook also writes beijing_clean_team<N>.csv.gz, which you keep for Week 2.

⏱ all week · keep it honest

Rules

  • Use the test year only in Task 6; start Part B from your merged export, not from train_raw.
  • Keep TEAM_ID and SEED fixed all week.
  • Discover the problems from the data — do not read the code that generates your merged file.
  • Every number you write must come from your executed cells.
